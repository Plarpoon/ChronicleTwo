# Chronicle Two

Chronicle Two is a decompilation project (and eventually port) of Dark
Chronicle/Dark Cloud 2 for the PlayStation 2. It targets the PAL release
(`SCES_511.90`): C++ that compiles, with the original Metrowerks toolchain, to
an executable byte-identical to the one on the disc.

## Building and running

1. Clone with submodules (`git clone --recurse-submodules`, or
   `git submodule update --init` in an existing clone).
2. Place the PAL disc image at `rom/pal/Dark Chronicle (PAL).iso`.
3. Run `./build.sh` to build the executable and verify it against retail, or
   `./run.sh` to also master a disc image with it and boot that in PCSX2.

`./dev.sh` opens a shell in the build container (`./dev.sh <command>` runs one
there). The scripts build the container image on first use; set
`REBUILD_IMAGE=1` after changing the `Dockerfile`.

The toolchain runs in an x86_64 Linux container under podman or docker. On an
Apple-silicon Mac that has to be an x86_64 [colima](https://github.com/abiosoft/colima)
VM, since the compiler cannot run under Rosetta emulation:

```
brew install colima docker
colima start --profile chronicletwo --arch x86_64 --cpu 4 --memory 8
```

The scripts find a running x86_64 colima profile by themselves; `BUILDER` and
`DOCKER_CONTEXT` override the choice.

## Decompiling

Every game translation unit is a file in `ps2/src`. A function or datum that
is not decompiled yet is an `INCLUDE_ASM` or `INCLUDE_RODATA` marker there,
which the build fills with retail's bytes; replacing a marker with C++ that
compiles to the same bytes keeps the executable identical.

- `./decompile.sh <symbol>` prints m2c's reading of a function.
- `./diff.sh <symbol>` diffs a function against retail with objdiff, and
  `./diff.sh --report` prints the progress report `./build.sh` ends with.
- objdiff's GUI works from the `objdiff.json` the build writes at the root.

Symbols are the compiler's mangled names, as listed in
`ps2/config/pal/main.symbols.txt`.

## Generated files

`ps2/asm/` (the executable split into assembly by splat), `build/` (objects,
the linked executable and the mastered disc image), `rom/pal/extracted/`,
`objdiff.json` and `progress/` are generated by the build and never committed.
The linker script, `ps2/config/pal/SCES_511.90.lcf`, is checked in; rerun
`scripts/build/lcf.py` after a unit is added, removed or moved in `main.yaml`.
